# Studio в основном приложении

Studio подключён на обычных маршрутах `/org/...`: обзор, события, игроки, игры, голосования, задолженности, оба вида шаблонов и профиль. Примерочная `/design-lab` остаётся отдельной страницей. Документация сохраняет прежнюю структуру и тёмную палитру.

## Что перенесено

- Golos Text с локальными файлами шрифта, светлая палитра, зелёные акценты, компактная навигация, шапка с выбором команды. На телефоне навигация открывается отдельной панелью.
- Обзор с реальным расписанием, календарём и показателями команды; списки событий и голосований; шаблоны; карточки игроков с реальными навыками и альтернативным табличным видом.
- Задолженности единым раскрывающимся списком: встреча и дата, сумма, оплата одного или всех взносов, отмена последней операции и выбор получателей напоминания.
- Общий `src/components/Select.tsx`: оформленные меню, текущий выбор, стрелки/Home/End/Enter/Escape/Tab, поиск набором текста, disabled/required, нативное значение для форм. Меню открывается вверх при недостатке места и не обрезается контейнером.

Основные обработчики, маршрутизация, API и проверки прав сохранены в `App.tsx`. Исправлен сброс прямых ссылок на событие и голосование во время начальной загрузки: очистка состояния теперь ждёт загрузки организаций. Новые представления находятся в `src/features/studio`, оформление — в `src/studio-theme.css`. Фото, номера и посещаемость из примерочной не подставляются реальным игрокам: доступный API не отдаёт фото, поэтому используются инициалы.

## Оплаты

`StudioBilling` вызывает существующий API `PUT /api/groups/:chatID/events/history/:instanceID/billing` только со статусом выбранного игрока. Backend обновляет переданные строки, сохраняя статусы остальных участников. При массовой отметке запросы идут последовательно; при частичной ошибке интерфейс показывает число сохранённых взносов. Отмена затрагивает только успешно сохранённые строки последнего действия. После операции обновляются задолженности и общая сумма. Отмена — отдельный запрос; уже отправленный запрос не отменяется закрытием страницы.

Предпросмотр напоминания показывает выбранных игроков. Публикация выполняется существующим API только по отдельной кнопке в диалоге.

## Проверки

`docker compose -f docker-compose.yml exec -T frontend npm run build` проходит: TypeScript и production-сборка Vite. `git diff --check` проходит. Контейнеры db, web, frontend и ml запущены.

В браузере проверена прямая ссылка на событие после начальной загрузки, основные девять разделов и вложенные редакторы, выбор типа игрока с клавиатуры, сохранение дня недели события, раскрытие составов игры, единичная оплата/отмена, частичная ошибка массовой оплаты/отмена, выбор получателей, ограничение доступа участника, ошибка загрузки задолженностей, меню и списки при ширине 390 px. Выпадающие меню примерочной проверены в светлом Studio и тёмной Arena.

Для проверки настоящего API создана локальная организация «Орбита · тестовая команда» с игроками, встречами и платежами. Наполнение, проверенные операции и ограничения локальной авторизации описаны в [LOCAL_DEMO_RU.md](LOCAL_DEMO_RU.md). Изолированный браузерный стенд ниже остаётся доступен для проверки ошибок и разных прав. Внешние публикации не выполнялись.

## Изолированный стенд для ручной проверки

Открыть на Vite dev-сервере: `http://localhost:5173/qa/studio.html`. Это настоящий `App` с подменёнными в этой вкладке ответами `/api/`. Внизу видна подпись «Тестовые данные · API изолирован»; раскрываемая панель показывает запросы на изменение. Данные существуют только в памяти вкладки. Стенд не входит в production-сборку.

Параметры:

- `?screen=billing` — задолженности; также доступны обычные разделы, например `members`, `events/301`, `event-templates/201`.
- `?role=member&screen=billing` — проверить отказ в доступе.
- `?screen=billing&failPayment=1` — ошибка второго взноса при массовой оплате Дмитрия.
- `?screen=billing&billingError=1` — ошибка загрузки списка.

Приложение меняет адрес на обычный маршрут. Для нового теста открывайте `/qa/studio.html` заново или нажимайте «Сбросить тесты»: полная перезагрузка уже изменённого адреса открывает основной продукт с реальным API. Перед проверкой изменений убедитесь, что подпись об изоляции видна. Это также относится к полной перезагрузке страницы при HMR.

## Навигация событий

В боковом меню один пункт «События». Внутри — «События», «Голосования» и «Шаблоны». В шаблонах дополнительный переключатель «Событий / Голосований». При переходе из бокового меню открывается список событий; если нет права на него, открывается первая доступная вкладка. Вкладки и типы шаблонов учитывают существующие права. Внутри встречи сохранены «Состав», «Голоса», «Оплата», «Партии».

Адреса `/events`, `/polls`, `/templates`, `/event-templates` и их вложенные страницы сохранены: выбранная вкладка определяется маршрутом, работает история браузера. «Примерочная» удалена из меню основного продукта; `/design-lab` доступен по прямому URL.

Для проверки роли с доступом только к шаблонам голосований в изолированном стенде используйте `?role=templates&screen=templates`.

После группировки навигации повторно проверены сборка, переходы между тремя вкладками и двумя типами шаблонов, кнопка «Назад» браузера, открытие списка событий из бокового меню, вид 390 px без горизонтального переполнения и роль с доступом только к шаблонам голосований.

## Распределение команд и прогноз

Колонки команд растягиваются до общей высоты и имеют общую верхнюю границу при разном числе игроков. В заголовках видны размеры составов; добавление третьей команды вынесено над сеткой. Пустые команды сохраняют область для переноса игроков.

`TeamForecast` показывает сравнение рейтингов с крупными процентами, числом игроков и средним рейтингом. Проценты используют прежний расчёт доли суммарного рейтинга. Это подписано в интерфейсе. При пустом составе проценты не выводятся; при неравных составах и нераспределённых игроках видны пояснения. Для трёх команд есть три попарных сравнения.

В изолированном стенде доступны сценарии `?screen=events/301&roster=uneven`, `roster=empty`, `roster=three`. Проверены неравные колонки, добавление пустой команды C, попарные значения, пустое состояние и ширина 390 px без горизонтального переполнения. Сборка TypeScript/Vite проходит.

## Темы оформления

В «Мой профиль → Оформление» доступны четыре карточки с превью: «Ночная арена», «Спортивный клуб», «Вишня» и исходная светлая тема. Переключатель из шапки удалён. На телефоне карточки располагаются одной колонкой и сохраняют текстовые названия. Новым пользователям по умолчанию показывается «Ночная арена»: фон `#101C30`, панели `#1A2B43`, текст `#EDF2F7`, голубой акцент `#69B7E8`. «Спортивный клуб» сочетает фон `#EEF2F6`, белые карточки, тёмно-синее меню `#142B49` и акцент `#3267CF`.

Выбор хранится в `localStorage` под ключом `teamtime-theme` и синхронизируется между вкладками. Сохранённая тема имеет приоритет. Начальная палитра применяется в `index.html` до загрузки React; при недоступном хранилище переключение работает на время текущего посещения. Хук `useProductTheme` находится в корне приложения, поэтому тема сохраняется при уходе из профиля, а синхронизация вкладок работает на любом разделе. Примерочная использует собственные темы.

Оформление доступно в локальном профиле, при ошибке загрузки статистики и без права `profile_read`. Личные данные и управление ролями сохраняют прежние проверки доступа. В локальном режиме запрос `/me`, требующий Telegram-авторизации, не выполняется.

Палитры и общие правила тёмного оформления находятся в `src/product-themes.css`, светлая тема — в `src/studio-theme.css`, переключатель — в `ThemeSwitcher.tsx`. Цвета рейтингов адаптируются к светлым и тёмным поверхностям. Проверены четыре варианта, сохранение после перезагрузки и переходов, мобильная ширина 390 px без горизонтального переполнения, локальный профиль, авторизованный профиль со статистикой и ограниченная роль в изолированном стенде. Production-сборка проходит.


## Настройки организации

Раздел «Настройки» в меню администратора открывает `/org/<orgKey>/settings`; прямой `/settings` также поддерживается. С обзора перенесены название, часовой пояс и действие «Опубликовать регистрацию». Название и часовой пояс отображаются как сведения: они сохраняются при подключении Telegram-группы, самостоятельное редактирование в веб-интерфейсе не добавлено. Оформление остаётся в личном профиле.

Публикация использует существующий API и право `templates_manage`, отправляет регистрационный опрос в Telegram-группу. Во время запроса кнопка недоступна для повторного нажатия; результат и ошибки отображаются общим уведомлением приложения. Участникам настройки скрыты, прямой переход показывает сообщение о недостаточных правах. Для проверки публикации без Telegram можно открыть `/qa/studio.html?screen=settings` (изолированный API).


## Пагинация событий

Список встреч разбит на страницы по 12, 24 или 28 событий. Фильтр статуса применяется до пагинации; его изменение, смена организации или размера страницы возвращают на первую страницу. Переключение «Плитки / Список» и возврат из встречи сохраняют текущую страницу. При сокращении результатов страница ограничивается последней доступной. API истории пока возвращает полный массив; пагинация выполняется в браузере и сокращает число одновременно отображаемых элементов.

Для проверки нескольких страниц без изменений в базе: `/qa/studio.html?screen=events&eventCount=65` (до 200 записей, изолированный API).


## Уведомления об ошибках

Ошибки операций, загрузки и проверки форм показываются компактными окнами снизу слева, не меняя раскладку страницы. Общий `useErrorState` сохраняет состояние ошибок для защиты пустых/загружаемых экранов, а `ErrorNotifications` выводит максимум три уведомления. Повторы объединяются, закрытие доступно вручную; автоматическое закрытие через 12 секунд приостанавливается при наведении или фокусе. Для открытого native dialog уведомления помещаются в его верхний слой, сохраняя положение относительно окна браузера.

`src/app/errors.ts` переводит известные ошибки API и сети; неизвестные технические сообщения заменяются понятным русским текстом. Русская валидация и сведения о частично сохранённых взносах сохраняются. API возвращает прежние ошибки; преобразование выполняется в клиенте.

Проверка переводов: `node --test qa/errors.test.mjs`. Изолированные UI-сценарии: `/qa/studio.html?screen=settings&errors=bot%20is%20not%20configured`, `/qa/studio.html?screen=billing&errors=bot%20is%20not%20configured` (публикация из диалога), `/qa/studio.html?screen=events&networkError=1`, `/qa/studio.html?screen=events&historyError=1`. Параметр `errors` отклоняет любые изменения только в тестовом API; Telegram и база не затрагиваются.


Пагинация состава команды использует тот же компактный компонент: 12, 24 или 28 игроков в списке и карточках. Поиск, фильтр типа и сортировка применяются ко всем загруженным игрокам до разбивки и возвращают на первую страницу. Переход между карточками и списком сохраняет страницу. Навигация подписана «Страницы игроков» для скринридеров. Проверено на локальной команде из 16 игроков: 12 + 4, поиск, сортировка общего рейтинга и смена размера страницы.


## Профиль отдельного игрока

Отступы профиля нормализованы в `src/features/studio/playerProfile.css`: 24 px между основными блоками на компьютере, 20 px на телефоне. Заголовок, сведения, имя, амплуа, навыки, связи и сохранение выровнены; навыки располагаются в двух колонках на широком экране и в одной на узком. Рейтинг использует акцентный цвет темы на нейтральной поверхности вместо динамического зелёно-жёлтого цвета.

Карточки амплуа показывают цветное фото только для выбранной роли. Остальные фото чёрно-белые; подписи контрастные на тёмном градиенте. Выбор дополнительно обозначен рамкой и `aria-pressed`. Проверены ширина 390 px, темы «Спортивный клуб»/«Ночная арена» и сохранение выбранной роли в изолированном QA API.

В связях игроков поле «Вес» переименовано в «Принципиальность». Рядом размещена кнопка «?» с пояснением влияния пожеланий на автораспределение и шкалы 1–10. Подсказка закрывается повторным нажатием, кликом снаружи, уходом фокуса или Escape.

Выбор игрока для связи вынесен в `PlayerPicker`: поиск по имени/нику (поиск по ID сохранён без отображения ID), имена слева, инициалы и ник отдельной строкой. Меню ограничено 480 px, учитывает место сверху/снизу и выводится через портал. Поддерживаются стрелки, Enter, Escape, закрытие снаружи и при уходе фокуса. Старые стили relation-picker удалены.

## Навигация событий и шаблонов

Раздел «События» открывает список встреч без общих вкладок. Голосование доступно из события; из его подробной страницы можно вернуться к исходному событию. Шаблоны событий и голосований находятся в блоке «Шаблоны» раздела «Организация». На страницах шаблонов активна иконка организации, доступны переход назад и переключение типа шаблонов. Пользователи с правами управления шаблонами без роли администратора видят в организации только разрешённые шаблоны. Прямые маршруты сохранены.
