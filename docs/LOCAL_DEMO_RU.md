# Локальная тестовая организация

В PostgreSQL локального Docker создана **«Орбита · тестовая команда»**, chat ID `-900001`.
Открыть основной интерфейс: <http://localhost:5173/org/-900001>.

Данные сохраняются в Docker volume PostgreSQL после перезагрузки страницы и перезапуска контейнеров. Это реальный API приложения.

Начальное наполнение:

- 16 вымышленных игроков с шестью навыками, игровыми амплуа, тренером, капитаном и связями между игроками.
- По 3 шаблона событий и голосований.
- 4 встречи относительно дня первого запуска: две прошедшие и две будущие, со связанными голосованиями.
- Распределения по командам, 6 результатов партий, 24 взноса. Четыре неоплаченных взноса по 600 ₽: у Дмитрия Соколова две встречи (1 200 ₽), у Ивана Петрова и Елены Новиковой — по одной. В разделе «Взносы» можно сравнить группу встреч с одиночным взносом.

## Повторное использование

При запущенном сервисе `db` выполнить из корня проекта:

```powershell
python db/seed-local.py
```

Скрипт обращается только к сервису `db` из корневого `docker-compose.yml`. Учётные данные берутся внутри контейнера. SQL находится в `db/seeds/local-demo.sql` и не включён в миграции: наполнение запускается только явно.

Все записи создаются одной транзакцией. Повторный запуск при существующем chat ID ничего не меняет и сохраняет пользовательские тестовые правки. При занятом диапазоне идентификаторов игроков скрипт прекращает работу. Относительные даты при повторном запуске не сдвигаются.

## Что можно проверить

Через реальный локальный API проверены чтение организации, игроков, событий, голосований, игр и задолженностей; изменение амплуа игрока с восстановлением; автоматическое распределение 12 игроков в две команды; сохранение взноса из браузера и его отмена. Повторное наполнение не создало дубликатов и сохранило промежуточную тестовую оплату.

Локально вход отключён. Личный профиль и управление ролями требуют Telegram-авторизации в существующем backend. Публикации в Telegram также требуют настроенного бота и настоящей группы. В тестовых данных используются вымышленные идентификаторы, публикации и объявления выключены, расписания не создаются; бот для этой проверки не запускается. Эти ограничения не обходятся тестовым наполнением.
